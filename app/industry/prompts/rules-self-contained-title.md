
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：产品名 / 套餐名 / 公司名 / 项目名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是版本号 / 代号 / 没信息量的 teaser（如 "What's new in October"、"Small is a feature"、"Day 1"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "What's new in October" + 来源 "Microsoft 365 官方博客" → "Microsoft 365 10 月更新：Copilot 进入更多套餐"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体产品时，用上位词（如"某协同办公产品"）兜底，绝不凭"行业常识"编一个具体产品 / 套餐 / 价格。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review / Pricing 这类解释、分析、教程或评测标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的产品或新数据，就改写成“发布 / 推出 / 上线 / 涨价”。只有原标题明确宣布了发布、推出、上线、调价或加价，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的公司、产品、项目名。
   例：原标题 "How Slack's new pricing works" → "Slack 新定价怎么算"，不能写成 "Slack 推出新定价"。
   例：原标题 "How to build an approval flow with Copilot" + 来源和正文明确是 Microsoft 365 → "Microsoft 365 如何用 Copilot 搭审批流"，不能只写成缺主体的 "如何用 Copilot 搭审批流"。
6. 本条的动作和背景里的旧变化要分清：原文把发布或调价写成过去的事（“At our customer conference, we introduced …”“Last month we raised prices …”“上个月我们调整了定价…”），本条是在讲用法、做演示或复盘时，标题写介绍、演示或讲解，把变化交代成此前的事；不能写成“推出 / 发布 / 上线 / 涨价”，否则读者会当成今天的新闻。只有原文明确某项变化是现在才生效或新增，才对那一项用对应动作。
   例：正文 "At Dreamforce we introduced the new Agentforce pricing … See how it works below" → "Salesforce 演示 Dreamforce 公布的 Agentforce 新计价方式"，不能写成 "Salesforce 在 Dreamforce 推出 Agentforce 新定价"。
